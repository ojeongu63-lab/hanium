# 제조공정 이상탐지 (한이음)

제조 설비의 공정 센서 데이터로 **불량을 사전에 잡아내는 비지도 이상탐지
시스템**. 정상 데이터만으로 LSTM-Autoencoder를 학습시켜 "평소와 다른 패턴"을
검출하고, 검출된 이상에 대해 **현장 조치 가이드까지 자동 생성**한다.

라벨이 거의 없는 실제 제조 현장 상황을 전제로 한다. 불량 샘플을 모아 지도학습
분류기를 만드는 대신, **정상 데이터의 재구성 오차**로 이상을 판정하는 방식을 썼다.

## 어떻게 여기까지 왔나

**1차 — CN7 사출성형 (`01-`).** 전처리부터 LSTM-Autoencoder 학습·평가까지
파이프라인 전체를 세웠다. 공정 드리프트 때문에 정상 샷의 재구성 오차가 날짜별로
수백 배씩 흔들리는 문제를 만나 롤링 z-score 보정까지 추가했다.

그런데 최종 성능이 **precision 0.04 (FP 195건)**에 그쳤다. 원인을 파고들어 보니
문제는 방법론이 아니라 데이터였다 — **평가셋의 진짜 불량이 18건뿐**이라 어떤
지표를 뽑아도 통계적으로 신뢰하기 어려웠다. 이 방법론이 정말 못 쓰는 건지,
아니면 CN7이라는 특정 데이터셋의 한계인지 판단할 수가 없었다.

**2차 — CNC 가공 (`02-`).** 그래서 **같은 방법론을 다른 제조공정 데이터에 그대로
적용해** 이 질문에 답하기로 했다. 결과는 **precision 0.91 / recall 0.91** — 방법론
자체는 유효했고, 1차의 낮은 성능은 데이터 한계였음이 확인됐다.

검증이 끝난 뒤 실제 운용에 필요한 것들을 붙여 나갔다:

- **MLflow** 실험 추적 + 모델 레지스트리 (champion alias로 서빙 버전 관리)
- **FastAPI** 추론 서버 — CSV 업로드 → 판정 + 피처별 기여도
- **드리프트 모니터링** — 운영 중 입력 분포 변화 감지
- **RAG 조치 가이드** — 불량 판정 시 공개 기술문서(Sandvik 밀링 트러블슈팅,
  OSHA 기계 안전수칙)를 검색해 원인 추정·권장 조치·안전수칙을 생성
- **LOOCV 검증** — 고정 분할 결과가 대표값인지 교차검증으로 확인
- **합성 시나리오** — 공구마모/이송축부하/진동 패턴을 주입한 데모용 입력

## 공통 방법론

두 트랙이 공유하는 뼈대:

```
원본 센서 CSV
   → 전처리 (중복 제거 · 이상치 제거 · 정규화 · train/eval 분할)
   → 정상 데이터만으로 LSTM-Autoencoder 학습
   → 재구성 오차 계산 → 임계값 초과 시 이상 판정
```

핵심은 **임계값을 라벨에서 역산하지 않는 것**이다. train(정상) 데이터의 오차
분포만으로 임계값을 정하고 eval에는 적용만 한다. 라벨을 보고 임계값을 맞추면
성능이 좋아 보이지만 실제 현장에서는 재현되지 않는다.

## 개발 환경

- Python 3.14, 패키지 관리는 [uv](https://docs.astral.sh/uv/)
- PyTorch **CPU 빌드** — 작업 서버(da20-suresoft)에 GPU가 없어서, 모델 크기와
  배치 크기를 CPU에서 감당 가능한 선으로 설계했다
- 트랙별로 `pyproject.toml`이 따로 있으므로 **해당 트랙 폴더 안에서** `uv sync`

```bash
cd 02-cnc-machining && uv sync && uv run pytest
```
