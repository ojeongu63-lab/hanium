# 데모 화면 — 동적 시뮬레이션 탭 설계

작성 2026-09-03. 선행: `2026-09-03-cnc-demo-page-design.md`(탭 1·2, 기록/실시간 하이브리드).

## 배경과 사용자 결정

정적 화면보다 "시간이 흐르면서 드리프트가 쌓이고, 루프가 반응하고, 불량 배치마다 RAG
진단이 열리는" 모습을 동적으로 보여 주면 미팅에서 이해가 쉽다는 요청.

- **재생 모드**: 이미 있는 실제 결과(타임라인 판정 1,050건 + 09-02 워커 로그 이벤트)를
  하루 단위로 재생한다. 그 자리에서 재학습을 돌리지 않는다.
- **좌우 분할**: 왼쪽 그래프 + 이벤트 로그, 오른쪽 현재 배치의 진단 패널.
- RAG의 실시간 연결은 "이 배치 지금 계산" 버튼으로 보여 준다(서버가 켜진 경우).

## 목표 / 비목표

**목표**

1. 세 번째 탭 "시뮬레이션": 시나리오를 고르고 재생하면 하루씩 그래프가 자라고,
   이벤트 날에는 자동 일시정지와 강조 카드, 불량 배치가 있는 날에는 오른쪽 진단
   패널이 그 배치로 바뀐다.
2. 진단 패널은 탭 1 카드의 축약판(판정·기여도 상위 5·플레이북 대조·패턴 진단·가이드)이며
   기록 배치에도 가이드 문장이 보인다(대표 가이드).
3. 서버가 켜져 있으면 "이 배치 지금 계산"으로 실제 `/predict`를 호출해 LLM이 방금 쓴
   가이드로 카드가 바뀐다.
4. pull만 받은 PC에서 파일로 열어도 재생은 전부 된다.

**비목표**

- 실시간 재학습·게이트 실행. 이벤트는 09-02 로그의 재생이다.
- 탭 1·2의 변경(공통 헬퍼 재사용만).
- 외부 라이브러리.

## 데이터 (내장 JSON 확장)

`build.py`의 `_batch`가 두 필드를 더 낸다. 채점 기록에 없던 값이라
`rag/eval_playbook.py`의 행에도 더하고 세 시나리오를 다시 돌린다.

```
batches[*] += {
  "top10": [[feature, z] ×10],          # 기여도 카드·플레이북 대조 표에 필요
  "matched": [feature, ...],            # fault.matched_features
  "alternatives": [name, ...], "other_group": {...} | null, "top_z": float
}
scenarios[*] += {
  "guides": { "<situation>|<verdict>": {response 요약} }   # 대표 가이드
}
```

**대표 가이드**: `build_demo.py`가 시나리오마다 (상황, 판정) 조합별 첫 불량 배치를
골라 `--representative` 실행 시 실제 서버 없이 `predict_experiment(..., openai_client)`로
가이드를 생성해 `data/rag/demo_guides.json`에 저장한다(OpenAI 키 필요, 없으면 건너뛰고
기존 파일 사용, 그것도 없으면 가이드 없이 생성). 조합은 타임라인 기준 최대 8개 안팎
(공구 마모/높은 일치, 고정구 풀림/높은 일치, 이송축 과부하/높은 일치, 공구 마모·이송축
과부하/복합 패턴, 고정구 풀림·공구 마모/약한 신호 등). 기록 배치의 카드에는 같은
조합의 대표 가이드를 "대표 가이드(같은 상황·판정의 배치에서 생성)"로 표시한다.

## 서버

`GET /demo/timeline/{scenario}/{day}/{index}` → `monitoring.simulate_timeline.generate_batch`로
같은 규칙의 배치 CSV를 만들어 돌려준다(`text/csv`). scenario ∉ 3종 또는 day·index 범위
밖 → 404. 원본 데이터셋이 없으면 404에 안내. 페이지의 "지금 계산"은 이 CSV를 받아
`/predict`에 올린다. `simulate_timeline.py`는 수정하지 않고 import만 한다(모듈이
`monitoring/` 최상위라 `sys.path`에 그 폴더를 더한다 — `rag/eval_playbook.py`와 같은 방식).

## 화면 (탭 3)

- 상단 컨트롤: 시나리오 3 버튼, ▶/❚❚, ⏭(한 걸음), ⏮(처음), 속도(0.5·1·2·4 s/일),
  "이벤트에서 자동 정지" 체크(기본 켬), 현재 Day/총일 표시.
- 왼쪽 위 그래프: 탭 2와 같은 좌표계(전체 일수로 고정)지만 현재 날짜까지만 점·선을
  그린다. 현재 날짜 세로선, 최근 10건 감시 창 음영, 상단에 "드리프트 감시: 연속 감지
  k/3" 상태(배율 ≥ 1.0인 날을 연속으로 세어 표시 — 실제 워커의 판정은 로그 이벤트가
  기준이며 이 표시는 안내용).
- 왼쪽 아래 이벤트 로그: 하루마다 한 줄("Day 23 · 불량 판정 3/5 · 평균 배율 1.12").
  이벤트가 있는 날은 종류별 색 카드(트리거/게이트 수치/거부 사유/추정 원인/섀도우/승격).
  최신이 아래에 붙고 자동 스크롤.
- 오른쪽 진단 패널: 그날 배치 5개 칩(정상 초록, 불량은 판정 색). 불량이 있으면 첫
  불량을 자동 선택. 카드: 판정+배율 막대, 기여도 상위 5, 플레이북 대조 표(선택·후보·다른
  구역 강조 — 탭 1과 같은 함수), 패턴 진단 배지+근거, 가이드(대표 가이드 또는 실시간
  결과). 실시간이면 "이 배치 지금 계산" 버튼, 결과 도착 시 소요 시간과 `versions`.
- 재생 엔진은 순수 함수 `stepState(state, data)`로 두어 이벤트 정지·끝 처리를 테스트할 수
  있게 한다(파이썬 테스트가 아니라 node로 돌리는 작은 JS 테스트 파일).

## 오류 처리

- 대표 가이드가 없는 조합 → "대표 가이드 없음 — 서버 실시간으로 계산 가능" 안내.
- `/demo/timeline` 404(데이터셋 없음) → 버튼 옆 오류 문자열, 재생은 계속.
- 파일로 열면 실시간 UI 없이 재생만.

  멈춤, 자동 정지 끄면 통과.

## 검증

1. 채점 재실행(3 시나리오, 온도 70일) → 새 필드 확인.
2. `build_demo.py --representative`로 대표 가이드 생성(키 필요) → `demo_guides.json`.
3. 파일로 열어 재생 3 시나리오 끝까지, 이벤트 정지·재개, 배치 칩 전환.
4. 서버로 열어 "지금 계산" 1건 → 가이드 도착.
5. 전체 테스트 + node 테스트.

## 알려진 한계

- 재생이므로 재학습·게이트는 실제로 돌지 않는다. 화면에 "2026-09-02 실행 기록 재생"을
  명시한다.
- 대표 가이드는 같은 상황·판정의 다른 배치에서 생성한 문장이다. 그 배치의 문장을
  보려면 "지금 계산".
- 온도 시나리오 Day 64 승격 뒤의 판정은 champion v1 기준 오프라인 계산이다(탭 2와 같음).
