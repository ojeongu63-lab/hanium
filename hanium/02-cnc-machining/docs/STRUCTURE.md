# 구조 한눈에 보기

CNC 가공 센서 데이터로 불량을 잡는 비지도 이상탐지 시스템입니다. 정상 데이터만으로
LSTM-Autoencoder를 학습해 "평소와 다른 패턴"을 재구성오차로 잡고(precision 0.91 /
recall 0.91), 운영 중 입력이 변하면 자동으로 재학습하되 검증을 통과할 때만 모델을
교체합니다. 실행 방법은 [README](../README.md), 설계 근거는 `docs/specs/`에 있습니다.

## 1. 세 단계

```
[학습]  원본 CSV → 전처리 → LSTM-AE 학습 → 임계값 → MLflow 등록 → champion 지정
[서빙]  CSV 업로드 → 양품/불량 판정 + 어떤 센서가 벗어났는지 + 현장 조치 가이드(RAG)
[운영]  드리프트 감지 → 재학습 → 게이트 → 섀도우 → 승격 / 거부(원인 추정 + 조치 제안)
```

- **학습**은 사람이 스크립트로 한 번 돌립니다. 임계값은 정상 데이터의 오차 분포에서만
  정하고 라벨에 맞추지 않습니다.
- **서빙**은 FastAPI 서버 하나입니다. champion 모델을 MLflow에서 읽어 옵니다.
- **운영**은 서버 옆에서 도는 감시 워커가 합니다. 같은 드리프트 신호가 "센서만
  이동"과 "설비 고장" 양쪽에서 나오므로, 재학습한 모델은 두 단계 검증(게이트 →
  섀도우)을 통과해야만 교체되고, 거부되면 원인을 추정해 현장 조치를 제안합니다.

## 2. 무엇이 어디에 있나

| 단계 | 폴더 | 안에 있는 것 |
|---|---|---|
| 학습 | `src/preprocessing/` | 피처 선택, 라벨, 정규화, train/eval 분할 |
| 학습 | `src/lstm_ae/` | 모델, 학습, 재구성오차 채점, 임계값, MLflow 기록 |
| 학습 | `scripts/` | 전처리 → 학습 → champion 승격 실행 진입점 3개 |
| 서빙 | `src/serving/` | FastAPI 앱(`/predict` 등)과 추론 로직 |
| 서빙 | `src/rag/`, `rag/` | 조치 가이드 생성. 안쪽이 라이브러리(플레이북 서명 대조 포함), 바깥쪽이 코퍼스 구축 스크립트와 원문(`rag/sources/`, 팀 작성 플레이북 포함) |
| 운영 | `src/monitoring/` | 요청 로그, 드리프트 판정, QC 라벨, 섀도우 기록, 원인 추정 |
| 운영 | `src/retraining/` | 트리거, 재학습, 게이트, 승격과 롤백 |
| 운영 | `monitoring/` | 감시 워커, 가상 운영 타임라인 시뮬레이터 |
| 검증 | `loocv/`, `synthetic/`, `augmentation/` | 교차검증, 데모용 합성 시나리오, 증강 실험. 서빙과 무관 |
| 데모 | `demo/` | 미팅 데모 페이지. 생성 스크립트, 재생 엔진(`sim_engine.js`), 생성물 `index.html`(서버 없이 열림, `/demo`로 열면 실시간) |
| 공통 | `tests/` | 단위 테스트 211개. `src/` 구조를 그대로 따름 |
| 공통 | `docs/` | 기능별 설계 스펙과 구현 계획(각 13건), 이 문서 |
| 공통 | `data/` | 원본, 전처리, 모델, MLflow, 로그. git에 없음 |

규칙 하나만 기억하면 됩니다. `src/`는 import해서 쓰는 라이브러리이고, 나머지 최상위
폴더는 각각 실행 스크립트와 그 결과물입니다. 이름이 겹치는 `src/rag/`와 `rag/`도
이 규칙을 따릅니다.

## 3. 처음 본다면 이 순서로

| 순서 | 파일 | 왜 |
|---|---|---|
| 1 | `src/preprocessing/split.py` | 어떤 실험이 학습과 평가에 쓰였는지. 모든 지표의 전제 |
| 2 | `src/lstm_ae/pipeline.py` | 학습부터 임계값까지 한 흐름 |
| 3 | `src/serving/app.py` | 실제 서비스 모양 |
| 4 | `src/retraining/gate.py` | 재학습 모델을 언제 믿는지 |
| 5 | `monitoring/drift_worker.py` | 운영 루프 전체가 한 파일에 |

## 4. 알아 둘 것

- `data/`는 용량 때문에 git에 없습니다. 배치 방법은 README 1-2절.
- 각 스크립트는 자기 파일 위치에서 프로젝트 루트를 역산합니다. 폴더 깊이를
  바꾸면 깨집니다.
- 알려진 한계(feedrate=20 조건의 오탐, 평가 창 민감도 등)는 각 스펙의 "알려진
  한계" 절에 정리돼 있습니다.
