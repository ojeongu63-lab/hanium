# CN7 LSTM 오토인코더 이상탐지 모델 설계

- 날짜: 2026-07-22
- 상태: 구현 완료, 실제 데이터 적용 및 사후 보정 완료. 최종 결과는 하단
  "실제 적용 결과 및 사후 보정" 섹션 참고.

## 배경

`docs/superpowers/specs/2026-07-21-cn7-preprocessing-pipeline-design.md`에서 설계·구현한
전처리 파이프라인의 출력(`data/processed/train.csv`, `eval.csv`, `scaler.json`)을 입력으로
받아, LSTM 기반 오토인코더로 실시간 이상탐지 모델을 학습하고 평가한다. 이 문서는
**드리프트 보정 → 시퀀스 구성 → 모델 아키텍처 → 학습 → 임계값/평가**까지를 다룬다.
드리프트 보정은 최초 설계에는 없었으나 실제 데이터 적용 중 필요성이 확인되어
추가되었다 (하단 "실제 적용 결과 및 사후 보정" 참고).

RAG 기반 불량유형 매칭(재구성오차가 큰 변수를 KAMP 가이드북/KOSHA 문서와 연결해 현장
조치 가이드를 제공하는 것)은 완전히 다른 기술 영역(문서 검색/매칭)이라 별도 스펙으로
다룬다. 이 스펙의 산출물(`eval_reconstruction_errors.csv`)이 그 다음 스펙의 입력이 된다.

**환경 제약**: 이 서버(da20-suresoft)는 GPU가 없는 24코어/125GB RAM CPU 전용 환경이다.
모델 크기·배치 크기·학습 시간 설계 전반에서 이 제약을 고려한다.

## 목표 / 비목표

**목표**
- `train.csv`(정상 가정, self-cleaned)로 학습한 LSTM 오토인코더가 `eval.csv`의 각 샷을
  복원하고, 샷별·변수별 복원오차를 계산한다.
- train 오차 분포에서 통계적 임계값을 정하고, eval에 적용만 해서 precision/recall을
  산출한다(라벨을 보고 임계값을 역산하지 않음 — 과적합 방지).
- 다음 스펙(RAG 매칭)이 그대로 소비할 수 있는 "샷별 + 변수별 복원오차" 산출물을 만든다.

**비목표 (다음 스펙 또는 범위 밖)**
- RAG 불량유형 매칭, KAMP 가이드북/KOSHA 문서 처리
- 실시간 스트리밍 추론/서빙, 프로덕션 배포/API화
- 하이퍼파라미터 자동탐색(AutoML, grid search) — 수동 조정만 다룸

## 프레임워크

**PyTorch**. CPU 전용 환경에서도 유연하고, 변수별 복원오차 분해 같은 커스텀 로직을
짜기 쉽다는 점에서 선택했다(사용자 확인).

## 입력

| 파일 | 내용 |
|---|---|
| `data/processed/train.csv` | 16,908행 × 24개 피처(스케일링됨) — 계량없는 샷 필터링 + self-cleaned unlabeled 데이터 (사후 보정 반영, 원래 34,886행에서 감소) |

| `data/processed/scaler.json` | 컬럼별 mean/std (복원오차를 실단위로 역변환할 때 사용) |

## 드리프트 보정 (사후 추가됨)

계량없는 샷 필터링(전처리 스펙 사후 보정)을 반영한 뒤에도, 정상 샷의 재구성오차가
날짜에 따라 극단적으로 달라지는 현상이 남아있었다(예: 2020-10-20까지는 거의 0에
가깝다가 10-29~30에는 수백~수만 배 커짐). train(unlabeled, ~10/20까지)과 eval
(labeled, 10/16~11/3)의 시간 범위가 거의 겹치지 않아 생기는 공정 드리프트로 판단됨.

**롤링 z-score**로 보정한다: 각 피처를 원본(전역 스케일링된) 값이 아니라, "최근
N=200샷의 rolling mean/std 대비 편차"로 변환해 LSTM-AE에 입력한다.
- train과 eval은 각자 자기 데이터 안에서만 롤링 통계를 계산한다(서로 시간이 겹치는
  구간이 있어 "train 뒤쪽=eval보다 과거"라는 가정이 항상 성립하진 않기 때문에,
  데이터셋 간 시딩은 하지 않는다).
- `window=200`(초기값, 조정 가능). 불량 사건(최대 17연속 샷)이 윈도우의 10% 미만만
  차지하도록 잡았다. 실측 결과 window=100은 불량 사건이 자기 자신의 기준선을
  오염시켜 성능이 뚜렷이 나빠졌고, window=200/400은 성능 차이가 거의 없어
  200을 유지했다.
- 각 데이터셋의 앞부분 `min_periods=30`(초기값) 미만 구간은 표본이 부족하므로,
  롤링 통계 대신 그 데이터셋 전체의 전역 평균/표준편차로 대체한다.
- 이 보정은 시퀀스 윈도우를 자르기 직전에 적용하며, 임계값/평가 방식(아래)은
  그대로 유지한다.

## 시퀀스 구성

시퀀스 길이 **N=12** (연속된 12개 샷을 하나의 시퀀스로 묶음). 실제 불량 사건이 연속된
17개 샷에 걸쳐 있었던 점을 고려해, 학습 윈도우 수를 충분히 확보하면서도 불량 구간이
여러 윈도우에 온전히 포착되도록 짧게 잡았다.

**train 시퀀스 — 비중첩(stride=N=12)**: 16,908행(사후 보정 반영) → 1,409개
윈도우(나머지 행은 버림). 각 샷이 정확히 하나의 윈도우에만 속하므로, 샷별 복원오차를
집계 없이 1:1로 바로 얻을 수 있다.

**eval 시퀀스 — 중첩 슬라이딩(stride=1)**: eval은 3,974행뿐이고 불량 18건 중 다수가
파일 앞부분(2020-10-16 05:21~05:57 사건)에 몰려 있어, train과 같은 비중첩 방식으로
자르면 나머지 처리 과정에서 하필 불량 구간의 샷이 통째로 잘려나갈 위험이 있다. 이를
피하기 위해 eval에는 stride=1 슬라이딩 윈도우를 적용해 가능한 모든 윈도우(3,963개)를
만들고, 각 샷의 최종 복원오차는 그 샷이 포함된 모든 윈도우에서 나온 오차의 **평균**으로
정의한다. 이러면 파일 맨 앞/맨 뒤 샷도 최소 1개 윈도우에는 포함되어, 3,974개 샷 전부가
빠짐없이 점수를 받는다.

train은 학습 효율을 위해 비중첩, eval은 완전한 커버리지를 위해 중첩 — eval은 학습에
전혀 사용되지 않으므로 이 비대칭이 리키지를 일으키지는 않는다.

## 모델 아키텍처

Encoder-Decoder LSTM 오토인코더 ("RepeatVector" 스타일):

```
입력 (batch, N=12, 24)
  → Encoder LSTM (input=24, hidden=64, 1층)
  → 마지막 hidden state (batch, 64)
  → Linear 병목 (64 → latent_dim=16)          # 잠재벡터 z
  → z를 시퀀스 길이만큼 반복 (batch, 12, 16)
  → Decoder LSTM (input=16, hidden=64, 1층)
  → 시점별 Linear 출력층 (64 → 24)
출력 (batch, N=12, 24)  # 복원된 시퀀스
```

**하이퍼파라미터는 초기값이며, 실제 데이터로 학습해보면서 조정할 수 있다**(사용자 확인
— 설계는 먼저 하되, 실제 적용 결과를 보고 다시 논의하기로 함). hidden=64, latent=16은
파라미터 수 약 46K개로 CPU 학습 부담이 적으면서도 24개 변수·12스텝 시퀀스의 복잡도에
비해 과도하지 않은 크기로 선택했다.

**손실 함수**: MSE(복원값, 원본값) — 시퀀스 전체(12×24=288개 값)에 대한 평균제곱오차.

## 학습 절차

- Optimizer: Adam, learning rate 1e-3 (초기값)
- Batch size: 64
- Epochs: 50 (초기값) — 별도 validation split은 두지 않고 train loss 추이만 관찰.
  언더/오버피팅이 관찰되면 조정한다.
- 학습 스크립트는 epoch별 loss를 출력해 CPU 환경에서도 진행 상황을 바로 확인할 수
  있게 한다.

## 샷별 복원오차 & 임계값

- 모델은 시퀀스(12스텝×24변수)를 통째로 복원하므로, 개별 샷의 오차는 "그 샷 위치에서
  24개 변수의 평균제곱오차"로 정의한다.
- 24개 변수별 개별 제곱오차도 함께 저장한다 — 평균만 남기면 다음 스펙(RAG 매칭)에서
  "어떤 변수가 문제였는지" 알 수 없기 때문이다.
- **임계값**: 최초 설계는 평균+3표준편차(3-시그마 규칙, 전처리 스펙과 동일한 방식)를
  따랐으나, 실측 결과 정상 샷 오차 분포가 정규분포가 아니라 오른쪽으로 크게 치우친
  분포라 3-시그마 임계값이 지나치게 보수적으로 잡혀(불량 18건 중 1건만 탐지) **train
  오차 분포의 95번째 백분위수**로 변경했다(사후 보정, 아래 참고). 여전히 train(정상
  가정) 샷들의 분포에서만 정하고 eval에는 적용만 한다 — 방법만 바뀌었을 뿐 "eval로
  역산하지 않는다"는 원칙은 그대로다.

## 평가

eval 샷별 오차가 임계값을 넘으면 "이상"으로 판정하고, `label` 컬럼(정상/가스/미성형)과
대조해 precision/recall을 산출한다.

**알려진 한계** (전처리 스펙에서 이미 기록된 것과 동일): 평가셋의 진짜 불량이 18건뿐이라
precision/recall 수치의 통계적 신뢰도가 낮다. 정량 지표와 별개로, 재구성오차 시계열이
실제 두 사건 구간(2020-10-16 05:21~05:57, 2020-11-03 04:44)과 정확히 맞아떨어지는지
정성적으로 확인하는 검증을 병행한다. 최종 실측 결과는 아래 "실제 적용 결과" 참고.

## 테스트 전략

실제 학습 자체(느리고 결과가 완전히 결정적이지 않을 수 있음)는 유닛테스트로 검증하지
않는다. 전처리 파이프라인 때와 같은 방식을 따른다:

- 시퀀스 구성 함수(train 비중첩 / eval 중첩+평균 집계)는 작은 합성 배열로 shape·값
  정확성을 테스트한다.
- 모델 forward pass는 랜덤 텐서로 입출력 shape만 확인한다(수렴 여부는 테스트 대상 아님).
- 샷별 오차 계산 + 임계값(백분위수) 로직은 합성 데이터로 테스트한다.
- 드리프트 보정(롤링 z-score) 로직도 작은 합성 배열로 손계산한 기댓값과 대조해
  테스트한다(초기 min_periods 미만 구간의 전역 평균 폴백 포함).

## 실제 적용 결과 및 사후 보정 (2026-07-22)

최초 설계(3-시그마 임계값, 드리프트 보정 없음)로 실제 데이터를 학습·평가한 결과
이상탐지가 완전히 실패했다(precision=0, recall=0 — 오히려 정상 샷 평균 오차가 불량
샷보다 높았음). 원인을 역추적하며 이 스펙에 없던 문제 3가지를 발견해 순서대로
반영했다:

1. **`cn7_unlabeled.csv`의 51.5%가 계량 없는(비정상) 사이클** — 전처리 스펙에 필터링
   단계로 반영(위 "입력" 참고). 반영 후: recall 0→0.056.
2. **train/eval 시간 범위가 거의 안 겹쳐 생기는 공정 드리프트** — 위 "드리프트 보정"
   섹션(롤링 z-score)으로 반영. 반영 후: 정상<불량 오차로 방향이 바로잡히고 오탐이
   2,144건→47건으로 감소(같은 95%ile 기준 이전 비교 시).
3. **3-시그마 임계값이 비대칭(오른쪽 치우친) 오차 분포에 부적합** — 백분위수 기반으로
   교체(위 "임계값" 참고).

**최종 결과** (window=200, min_periods=30, threshold_percentile=95, seed=42로 재현
가능): `threshold=1.172`, `precision=0.044`, `recall=0.5`(불량 18건 중 9건 탐지),
`tp=9 fp=195 fn=9 tn=3761`. 정상 샷 평균 오차 0.820 < 불량 샷 평균 오차 1.448.

**국소적 신호 확인**: 드리프트 구간을 제외하고 실제 불량 사건(2020-10-16 05:00~06:10)
구간만 놓고 비교하면 불량 샷 오차 중앙값(0.055)이 정상 샷 중앙값(0.015)의 약 3.6배로,
모델이 실제 불량 신호를 포착하고 있음을 확인했다.

**한계**: 평가 불량이 18건뿐이라 이 precision/recall 수치의 신뢰구간은 넓다.
`detrend_window`를 100/200/400으로 바꿔가며 재실험한 결과 100은 불량 사건 자체가
자신의 롤링 기준선을 오염시켜 뚜렷이 나빠졌고, 200과 400은 성능이 거의 동일했다 —
반면 `threshold_percentile`을 85~97 사이에서 바꾸면 recall 0.44~0.61, 오탐
130~530건 사이에서 크게 움직인다. 이는 모델 자체의 한계라기보다 "불량을 더 잡을지
오탐을 줄일지"의 정책적 트레이드오프이며, 표본이 18건뿐이라 어느 지점이 "정답"인지
통계적으로 확정할 수 없다. 이 스펙은 현장 재현율을 우선한다는 원 설계 방향에 따라
95%ile(recall=0.5)을 최종값으로 채택했다.
- eval의 윈도우 간 평균 집계 로직은 작은 합성 예시로 기대값과 대조해 검증한다.
